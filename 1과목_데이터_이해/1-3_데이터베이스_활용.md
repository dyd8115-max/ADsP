# 기업 내부 데이터베이스

## 기업에서 쓰이는 DB/시스템 관련 용어

| 구분 | 정의 | 특징/예시 | 성격 |
|---|---|---|---|
| 인하우스 DB | 기업이 직접 구축·운영하는 내부 데이터베이스 | 외부 업체에 맡기지 않고 자체적으로 데이터를 수집·관리<br>보안성과 자체 활용도가 높음 | **운영 형태**<br>(DB의 소유·구축 방식) |
| OLTP | 실시간으로 짧은 트랜잭션을 처리하는 시스템 | 은행 입출금, 주문 처리 등<br>빈번한 삽입·수정·삭제(쓰기 중심)<br>응답 속도가 빠름 | **처리 방식**<br>(DB를 다루는 방법) |
| OLAP | 대량의 데이터를 다양한 관점에서 분석하는 시스템 | 경영 의사결정 지원, 다차원 분석(큐브)<br>읽기 중심, 집계·통계 연산이 많음 | **처리 방식**<br>(DB를 다루는 방법) |
| CRM | 고객 관계 관리 시스템 | 고객 구매 이력·상담 기록 등을 분석해 신규 고객 창출, 이탈 방지 | **응용 솔루션**<br>(Salesforce 등) |
| SCM | 공급망 관리 시스템 | 원재료 → 생산 → 유통 전체 흐름 관리<br>재고·물류 최적화 | **응용 솔루션**<br>(SAP SCM 등) |
| ERP | 전사적 자원관리 — 기업의 자원(인사·재무·생산 등)을 통합 관리하는 패키지 | 의사결정을 지원하는 여러 모듈을 통합한 어플리케이션 제공<br>부서 간 자원 요청 시 바로 구매·생산까지 연계되어 업무 효율 ↑ | **응용 솔루션**<br>(SAP, 더존 등) |
| EAI | 기업 내 모든 서비스(시스템)를 중앙에서 관리하는 미들웨어 솔루션 | 시스템 간 연결 루트를 간소화해 통합 관리 | **응용 솔루션**<br>(미들웨어) |
| KMS | 지식 경영 시스템 | 직원 개개인의 지식·경험·노하우를 기업 차원에서 통합·관리<br>문제 해결 능력 향상이 목적 | **응용 솔루션** |
| BI | 기업의 의사결정 프로세스를 지원하는 도구/시스템 | 보유 데이터를 정리·분석하여 리포트 중심으로 제공 | **응용 솔루션**<br>(Tableau, Power BI 등) |
| RTE | 실시간 기업 | 업무 프로세스에서 발생하는 정보를 실시간으로 통합·전달하여 신속한 대응이 가능한 "스피드 경영" | **경영 개념**<br>(제품 아님) |

## OLTP vs OLAP

| 구분 | OLTP | OLAP |
|---|---|---|
| 목적 | 실시간 거래 처리 | 데이터 분석·의사결정 지원 |
| 데이터 | 최신 데이터 | 과거~누적 데이터 |
| 연산 | 단순 삽입·수정·삭제 (쓰기 중심) | 집계·통계·다차원 분석 (읽기 중심) |
| 예시 | ATM 입출금, 쇼핑몰 주문 | 매출 분석 리포트, BI 대시보드 |

---

## CRM vs SCM vs ERP

| 구분 | CRM | SCM | ERP |
|---|---|---|---|
| 초점 | 고객 | 공급망(원재료→생산→유통) | 기업 내부 전체 자원(인사·재무·생산 등) |
| 목적 | 신규 고객 창출, 고객 이탈 방지 | 물류·재고 효율화를 통한 비용 절감 | 부서 간 자원 통합으로 경영 효율화 |

> 인하우스 DB, OLTP, OLAP, CRM, SCM, ERP, EAI, KMS, BI, RTE 모두 기업이 내부적으로 구축·운영하는 대표적인 데이터베이스 활용 형태

## 부문별 기업 내부 데이터베이스

| 부문 | 주요 내용 |
|---|---|
| 제조 | 부품 표준화, 설계 정보 공유 — **ERP·SCM** 도입, 실시간 기업 지향 |
| 금융 | 은행 업무 전산화 → **EAI**로 시스템 통합, **데이터 웨어하우스** 고도화 |
| 유통 | **CRM·SCM** 구축, 전자태그(RFID)로 실시간 재고·물류 관리 |

# 데이터 웨어하우스와 관련 용어

| 용어 | 설명 |
|---|---|
| 데이터 웨어하우스 | 의사결정 지원을 위해 여러 원천 시스템의 데이터를 **주제 중심으로 통합·누적**한 저장소 |
| 데이터 마트 | 데이터 웨어하우스에서 **특정 부서·주제용으로 추출한 작은 저장소** |
| ETL | 원천 데이터를 **추출 → 변환 → 적재**하는 과정 |
| ODS | 여러 운영 시스템의 데이터를 통합해 **실시간에 가깝게 보관하는 중간 저장소** |
| 데이터 레이크 | 정형·반정형·비정형 데이터를 **원래 형태 그대로** 대량 저장하는 저장소 |

## 데이터 웨어하우스의 4가지 특징 ⭐

| 특징 | 설명 |
|---|---|
| 주제 지향성 | 업무 기능이 아닌 고객·상품 같은 **주제 중심**으로 구성 |
| 통합성 | 여러 시스템의 데이터를 **일관된 형식으로 통합** |
| 시계열성 | 과거부터 현재까지 **시간에 따른 이력**을 보관 |
| 비휘발성 | 적재 후 **수정·삭제 없이 읽기 전용** |

> 3과목 데이터 마트 단원과 겹치는 내용. 1과목에서는 개념, 3과목에서는 R 구현 위주로 나온다.

| 무역·물류 | **EDI**(전자문서교환), **VAN**(부가가치통신망), **CALS**(제품 설계부터 폐기까지 전 과정 정보 공유), 항만·철도 운영 정보 시스템 |
