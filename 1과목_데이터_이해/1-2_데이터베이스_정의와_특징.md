# 데이터베이스의 정의와 특징

> 1과목 데이터 이해 › 1장 데이터의 이해

---

# 데이터베이스

## 정의

| 구분 | 정의 |
|---|---|
| DB (Database) | 여러 사람이 공유하고 사용할 목적으로 **통합·저장된 데이터의 집합** |
| DBMS (DataBase Management System) | DB를 효율적으로 관리·운영하기 위한 **소프트웨어 시스템** |

> DB는 "데이터 집합 그 자체", DBMS는 "그 데이터를 다루는 프로그램" (예: MySQL, Oracle, PostgreSQL)

---

## 특징

### 1. 일반적 특징

| 특징 | 설명 |
|---|---|
| 통합된 데이터 | 중복을 최소화한 데이터의 집합 |
| 저장된 데이터 | 컴퓨터가 접근 가능한 매체에 저장됨 |
| 공용 데이터 | 여러 사용자/응용프로그램이 공동으로 소유·이용 |
| 운영 데이터 (변화하는 데이터) | 조직의 고유 기능을 수행하기 위해 반드시 필요하며, 끊임없이 삽입·삭제·갱신되는 데이터 |

### 2. 다양한 측면에서의 특성

| 측면 | 설명 |
|---|---|
| 정보의 축적 및 전달 측면 | 기계 가독성: 정보처리기기가 읽고 씀<br>검색 가능성: 필요한 정보를 검색할 수 있음<br>원격 조작성: 통신망을 통해 원거리에서도 온라인으로 이용 가능 |
| 정보 이용 측면 | 이용자 요구에 따라 다양한 정보를 신속·경제적으로 획득·검색 가능 |
| 정보 관리 측면 | 방대한 정보를 체계적으로 축적하고, 추가·갱신이 용이함 |
| 정보기술 발전 측면 | 정보처리·검색·관리 소프트웨어 등 네트워크 기술 발전을 견인 |
| 경제·산업적 측면 | 인프라로서 경제·산업·사회 활동의 효율성을 높이고 국민 편의를 증진하는 수단 |

## 데이터베이스의 발전

| 시기 | 내용 |
|---|---|
| 1950년대 | 미국에서 군비 상황을 집중 관리하기 위해 '데이터의 기지'라는 뜻으로 처음 사용 |
| 1963년 | 미국 SDC가 개최한 심포지엄에서 공식 용어로 사용 |
| 1975년 | 미국 CAC가 KORSTIC을 통해 서비스한 것이 국내 데이터베이스의 시초 |
| 1980년대 중반 | 국가 기간전산망 사업으로 국내 구축 본격화 |

## 데이터베이스 관련 용어

| 용어 | 설명 |
|---|---|
| 메타데이터 | **데이터에 관한 데이터** — 데이터의 구조·정의·속성을 설명 |
| 데이터 사전 | 데이터 요소의 이름·형식·의미 등을 정의해 둔 목록 |
| 인덱스 | 검색 속도를 높이기 위해 데이터 위치를 따로 정리한 구조 (책의 색인) |
| 스키마 | 데이터베이스의 구조와 제약 조건을 정의한 것 |
| 트랜잭션 | 하나의 논리적 작업 단위 — 전부 반영되거나 전부 취소됨 |

# 데이터베이스의 종류

| 종류 | 정의 | 특징/예시 |
|---|---|---|
| 계층형 (Hierarchical) | 데이터를 **트리(Tree) 구조**로 구성한 가장 초기 형태의 DB | 부모-자식 관계로 데이터 표현<br>구조 변경이 까다롭고 탐색 비효율적 → 현재는 거의 사용 안 함 |
| 망형 (Network) | 계층형의 단점을 개선해 데이터끼리 **그래프 형태로 연결**한 구조 | 계층형보다 유연하지만, 프로그래머가 전체 구조를 알아야 해서 복잡함 → 현재는 거의 사용 안 함 |
| 관계형 (Relational, RDB) | 데이터를 **행과 열로 이뤄진 테이블**에 저장 | 테이블 간 JOIN으로 관계 표현<br>SQL로 조작·검색<br>예: Oracle, MySQL, MS-SQL, MariaDB, PostgreSQL |
| 객체지향형 (Object-Oriented) | 데이터를 **객체(Object) 형태**로 저장 | 객체지향 프로그래밍 개념(클래스, 상속 등)을 DB에 적용 |
| 객체관계형 (Object-Relational) | 관계형 DB에 객체지향 개념을 일부 도입한 형태 | 오늘날 많은 RDB(Oracle, DB2 등)가 이 기능을 포함 |
| NoSQL (Not only SQL) | 관계형이 아닌 **비관계형 DB** | 고정된 스키마 없이 유연하게 저장<br>비정형·대용량 데이터의 분산 처리에 용이<br>예: MongoDB, Cassandra, HBase, DynamoDB |

---

## 관계형 vs NoSQL (가장 많이 쓰이는 두 종류 비교)

| 구분 | 관계형 (RDB) | NoSQL |
|---|---|---|
| 구조 | 고정된 스키마, 테이블(행·열) | 스키마 유연함 (문서/키-값/그래프 등) |
| 데이터 | 정형 데이터 중심 | 반정형·비정형 데이터 처리에 강함 |
| 질의 언어 | SQL | DB마다 다름 (REST API 등) |
| 확장 방식 | Scale-up (수직 확장) 중심 | Scale-out (수평 확장)에 유리 |
| 예시 | MySQL, Oracle, PostgreSQL | MongoDB, Cassandra, DynamoDB |

---

## NoSQL 유형

| 유형 | 저장 방식 | 예시 |
|---|---|---|
| 키-값 | 키 하나에 값 하나를 대응 | Redis, DynamoDB |
| 문서 | JSON 같은 문서 단위로 저장 | MongoDB, CouchDB |
| 열 기반 | 행이 아닌 열 묶음 단위로 저장 | HBase, Cassandra |
| 그래프 | 노드와 관계(간선)로 저장 | Neo4j |

> 구글 빅테이블이 열 기반 NoSQL의 원형이고, HBase는 이를 본뜬 하둡 기반 DB다.

# SQL (Structured Query Language)

## 정의

| 구분 | 설명 |
|---|---|
| SQL | 관계형 데이터베이스(RDB)에서 **데이터를 정의·조작·제어하기 위한 표준 언어** |

> SQL은 RDBMS(MySQL, Oracle, PostgreSQL 등)에서 데이터를 다루는 **공용 언어**로, 모든 관계형 DB에서 사용 가능

---

## SQL의 특징

| 특징 | 설명 |
|---|---|
| 표준화 | 국제 표준(ISO/IEC)으로 모든 RDB에 공통으로 적용 |
| 사용 용이 | 영어와 유사한 문법으로 학습과 사용이 비교적 쉬움 |
| 비절차적 언어 | "어떻게"가 아닌 "무엇을" 원하는지만 명시하면 DB가 처리함 |
| 보관된 프로시저 | 복잡한 연산을 저장된 프로시저로 미리 정의해 재사용 가능 |
| 호스트 언어와 연동 | Java, Python 등 다양한 프로그래밍 언어에서 SQL을 포함해 사용 가능 |

---

## SQL 명령어 분류

### 1. DDL (Data Definition Language) — 데이터 정의어

데이터베이스 구조(스키마)를 정의·변경·삭제하는 명령어. **데이터 자체를 다루지 않음**.

| 명령어 | 기능 | 대표 예시 |
|---|---|---|
| CREATE | 새로운 테이블/스키마/DB 생성 | `CREATE TABLE users (id INT, name VARCHAR(50));` |
| ALTER | 기존 테이블 구조 변경 (컬럼 추가/삭제/수정) | `ALTER TABLE users ADD age INT;` |
| DROP | 테이블/스키마/DB 삭제 | `DROP TABLE users;` |
| TRUNCATE | 테이블의 모든 데이터 삭제 (구조는 유지) | `TRUNCATE TABLE users;` |

> DDL은 "데이터를 담을 틀을 만들거나 수정하는" 명령어. 실행 즉시 반영되며 롤백 불가(AUTOCOMMIT)

---

### 2. DML (Data Manipulation Language) — 데이터 조작어

테이블에 저장된 **데이터 자체를 조회·삽입·수정·삭제**하는 명령어.

| 명령어 | 기능 | 대표 예시 |
|---|---|---|
| SELECT | 테이블에서 데이터를 조회 | `SELECT * FROM users WHERE age > 20;` |
| INSERT | 새로운 데이터 행 삽입 | `INSERT INTO users VALUES (1, 'John', 25);` |
| UPDATE | 기존 데이터 수정 | `UPDATE users SET age = 26 WHERE id = 1;` |
| DELETE | 데이터 행 삭제 | `DELETE FROM users WHERE id = 1;` |

> DML은 "데이터를 다루는" 명령어. COMMIT/ROLLBACK으로 트랜잭션 제어 가능

---

### 3. DCL (Data Control Language) — 데이터 제어어

사용자 권한을 부여·회수하는 명령어.

| 명령어 | 기능 | 대표 예시 |
|---|---|---|
| GRANT | 특정 사용자에게 권한 부여 | `GRANT SELECT, INSERT ON users TO user1;` |
| REVOKE | 사용자로부터 권한 회수 | `REVOKE DELETE ON users FROM user1;` |

> DCL은 "누가 무엇을 할 수 있는지 제어"하는 명령어. 보안 및 접근 제어 목적

---

### 4. TCL (Transaction Control Language) — 트랜잭션 제어어

데이터베이스 트랜잭션을 제어하는 명령어. DML 실행 후 **변경 사항을 확정 또는 취소**할 때 사용.

| 명령어 | 기능 | 대표 예시 |
|---|---|---|
| COMMIT | 현재 트랜잭션의 변경 사항을 **영구 저장** | `COMMIT;` |
| ROLLBACK | 현재 트랜잭션의 변경 사항을 **이전 상태로 복원** | `ROLLBACK;` |
| SAVEPOINT | 트랜잭션 내에서 **임시 저장점 지정** (부분 롤백 가능) | `SAVEPOINT sp1;` |

> TCL은 "DML 작업의 결과를 확정 또는 취소"하는 명령어. 데이터 무결성 보장

## SQL 조회 기본 — 결과값 문제 대비

```sql
SELECT 컬럼, 집계함수(컬럼)     -- 5
FROM 테이블                     -- 1
WHERE 조건                      -- 2
GROUP BY 컬럼                   -- 3
HAVING 그룹 조건                -- 4
ORDER BY 컬럼 [ASC | DESC];     -- 6
```

> 실행 순서: **FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY**

| 구분 | 내용 |
|---|---|
| 집계 함수 | `COUNT`, `SUM`, `AVG`, `MAX`, `MIN` — **NULL은 계산에서 제외**. `COUNT(*)`만 NULL 포함 행 수를 셈 |
| AVG 함정 | `AVG(컬럼)`은 NULL을 뺀 개수로 나눔 → `SUM(컬럼)/COUNT(*)`와 다를 수 있음 |
| WHERE vs HAVING | WHERE는 **그룹화 전 행**을, HAVING은 **그룹화 후 그룹**을 거름. 집계함수 조건은 HAVING에 |
| LIKE | `%`는 0개 이상 임의 문자, `_`는 정확히 1개 문자 |
| DISTINCT | 중복 제거 |

### JOIN

| 종류 | 결과 |
|---|---|
| INNER JOIN | 양쪽 모두 일치하는 행만 |
| LEFT OUTER JOIN | 왼쪽 전체 + 오른쪽 일치 행 (없으면 NULL) |
| RIGHT OUTER JOIN | 오른쪽 전체 + 왼쪽 일치 행 |
| FULL OUTER JOIN | 양쪽 전체 |
| CROSS JOIN | 모든 조합 — 행 수 = 왼쪽 × 오른쪽 |
