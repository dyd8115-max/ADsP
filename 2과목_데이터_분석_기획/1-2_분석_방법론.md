# 분석 방법론

> 2과목 데이터 분석 기획 › 1장 데이터 분석 기획의 이해

---

## 분석 방법론의 개요

### 분석 방법론 (Analytics Methodology)

| 개념 | 정의 |
|---|---|
| **분석 방법론** | 주어진 과제를 해결하기 위해 조직이 **어떠한 절차로 작업을 수행해 나갈 것인지 일련의 절차를 정의**한 것 |

---

## 분석 방법론의 필요성

| 필요성 | 설명 |
|---|---|
| **조직 내 정착** | 데이터 분석이 조직에 정착하기 위해서는 **체계화한 절차와 방법이 정리된 방법론 수립이 필수적** |
| **품질과 성공 가능성 확보** | 분석 프로젝트가 **개인의 역량이나 우연한 성공에 기인해서는 안 됨**<br>일정 수준의 품질을 갖춘 산출물과 성공 가능성을 확보·제시할 수 있어야 함 |
| **구성 요건** | 따라서 방법론은 **상세한 절차, 방법, 도구와 기법, 템플릿과 산출물**로 구성되어야 함 |

> **기업의 의사결정을 방해하는 요소**
> - **고정관념**: 기존 사고의 틀에 갇혀 새로운 가능성을 보지 못함
> - **편향된 생각**: 특정 방향으로 치우친 판단
> - **프레이밍 효과**: 동일한 사건이나 상황을 두고도 **제시 방식에 따라 개인의 판단이나 선택이 달라지는 현상**

---

## 분석 방법론의 생성과정

방법론은 **암묵지와 형식지의 상호작용(SECI 모델)**을 통해 만들어진다.

| 단계 | 변환 | 설명 |
|---|---|---|
| **1. 형식화** | 암묵지 → 형식지 | 개인의 경험과 노하우가 문서로 표현됨 |
| **2. 체계화** | 형식지 → 형식지 | 조직의 형식지가 결합·정리되어 **방법론**이 됨 |
| **3. 내재화** | 형식지 → 암묵지 | 체계화된 방법론을 학습·체화하여 개인의 암묵지로 발전 |

```
개인의 암묵지 → 조직의 형식지 → 체계화된 방법론 → 개인의 암묵지
        (형식화)        (체계화)          (내재화)
```

> **핵심**: 방법론은 한 번 만들어지고 끝나는 것이 아니라, **순환하며 지속적으로 발전**한다.

## 업무 특성에 따른 적용 모델

### 1️⃣ 폭포수 모델 (Waterfall Model)

| 항목 | 내용 |
|---|---|
| **진행 방식** | 단계를 거쳐 **순차적으로 진행**하는 하향식(Top-down) 방법 |
| **핵심 규칙** | 현재 단계가 **완료되어야** 다음 단계로 진행 가능 |
| **피드백** | 문제나 개선사항 발생 시 **이전 단계로 돌아가 피드백 과정 수행 가능** |

> 단계 구분이 명확해 관리가 쉽지만, 요구사항이 초기에 확정되어야 한다.

---

### 2️⃣ 프로토타입 모델 (Prototype Model)

| 항목 | 내용 |
|---|---|
| **진행 방식** | **사용자 중심**의 개발 방법 |
| **적용 상황** | 고객의 요구를 **완전히 이해하지 못한 경우** 적용 |
| **핵심 절차** | 일부분을 먼저 개발 → 사용자 요구 분석 → 정당성 점검 → 성능 평가<br>→ 개선 작업을 반복하며 **점진적으로 시스템 개발** |

> 요구사항이 불명확할 때 유용하며, 사용자 피드백을 빠르게 반영할 수 있다.

---

### 3️⃣ 나선형 모델 (Spiral Model)

| 항목 | 내용 |
|---|---|
| **진행 방식** | 반복을 통해 **점증적으로 개발** (프로토타입 모델과 유사) |
| **프로토타입과의 차이** | 사용자 요구보다 **위험 요소를 사전에 제거하는 것**에 초점 |
| **장점** | **처음 시도하는 프로젝트**에 적용이 용이 |
| **단점** | 관리 체계를 효과적으로 갖추지 못하면 **복잡도가 상승**하는 문제 발생 |

---

### 모델 비교

| 구분 | 폭포수 모델 | 프로토타입 모델 | 나선형 모델 |
|---|---|---|---|
| **진행 방식** | 순차적·하향식 | 반복적·점진적 | 반복적·점증적 |
| **초점** | 단계별 완결성 | **사용자 요구** | **위험 요소 제거** |
| **적용 상황** | 요구사항이 명확할 때 | 요구사항이 불명확할 때 | 처음 시도하는 프로젝트 |

## 계층적 프로세스 모델 (Hierarchical Process Model)

일반적으로 분석 방법론은 **계층적 프로세스 모델의 형태**로 구성된다.

### 3계층 구조

| 계층 | 정의 |
|---|---|
| **단계 (Phase)** | 프로세스 그룹을 통해 완성된 **산출물이 생성되는 최상위 계층** |
| **태스크 (Task)** | 단계를 구성하는 **단위 활동**으로, 물리적·논리적 단위로 품질검토가 가능한 항목 |
| **스텝 (Step)** | **입력 – 처리 및 도구 – 출력**으로 구성된 **가장 작은 단위 프로세스** |

```
단계 (Phase)
  └─ 태스크 (Task)
       └─ 스텝 (Step)
```

| 관계 | 설명 |
|---|---|
| **구성 관계** | 최상위 계층은 **몇 개의 단계**로 구성<br>하나의 단계는 **여러 개의 태스크**로 구성<br>하나의 태스크는 **여러 개의 스텝**으로 구성 |
| **WBS 대응** | **스텝**은 WBS(Work Breakdown Structure)의 **워크패키지**에 해당 |

> **핵심**: 단계 → 태스크 → 스텝으로 내려갈수록 작업 단위가 세분화되며, 최하위 스텝은 항상 "입력–처리–출력" 구조를 갖는다.

## 전통적인 분석 방법론

대표적인 전통 분석 방법론으로 **KDD**와 **CRISP-DM** 두 가지가 있다.

---

### 1️⃣ KDD 분석 방법론

| 개념 | 정의 |
|---|---|
| **KDD**<br> | 데이터로부터 **통계적 패턴이나 지식을 찾기 위해 체계적으로 정리한 데이터 마이닝 프로세스** |

| 특징 | 설명 |
|---|---|
| **적용 범위** | 데이터베이스에서 의미 있는 지식을 탐색하는 데이터 마이닝을 시작으로<br>**기계학습, 인공지능, 시각화** 등에서 응용 가능한 구조 |
| **구성** | 5단계 프로세스로 구성 |

> **데이터 마이닝 프로세스**: 대용량 데이터에서 의미 있는 패턴과 규칙을 발견하는 과정

---

#### KDD 프로세스 5단계

| 단계 | 명칭 | 주요 활동 |
|---|---|---|
| **1단계** | **데이터셋 선택**<br>(Selection) | - 비즈니스 도메인에 대한 이해와 프로젝트 목표 설정이 필수<br>- 분석에 필요한 데이터를 선택하고 **타깃 데이터 생성** |
| **2단계** | **데이터 전처리**<br>(Preprocessing) | - 잡음, 이상치, 결측치를 파악하여 제거하거나 의미 있는 데이터로 재가공<br>- 추가 데이터셋이 필요하면 **1단계를 다시 실행** |
| **3단계** | **데이터 변환**<br>(Transformation) | - 변수를 생성·선택하고 데이터의 **차원을 축소**<br>- **학습용 데이터와 검증용 데이터를 분리** |
| **4단계** | **데이터 마이닝**<br>(Data Mining) | - 학습용 데이터로 분석 목적에 맞는 마이닝 기법 선택 및 알고리즘 적용<br>- 필요에 따라 **전처리·변환 프로세스도 추가 수행** |
| **5단계** | **해석과 평가**<br>(Interpretation/Evaluation) | - 분석 목적과의 일치성을 확인하고 평가<br>- 발견한 지식을 **업무에 활용하기 위한 방안 마련** |

> **피드백 구조**: 2단계에서 데이터가 부족하면 1단계로, 4단계에서 필요하면 2·3단계로 되돌아갈 수 있다.

---

### 2️⃣ CRISP-DM 분석 방법론

| 개념 | 정의 |
|---|---|
| **CRISP-DM** | KDD와 유사하나 **보다 세부적으로 구성**된 계층적 프로세스 모델 |

#### 4레벨 구조

기존 계층 프로세스의 "단계–태스크–스텝"과 달리 **4개 레벨**로 구성된다.

| 레벨 | 명칭 |
|---|---|
| **Level 1** | 단계 (Phase) |
| **Level 2** | 일반화 태스크 (Generic Task) |
| **Level 3** | 세분화 태스크 (Specialized Task) |
| **Level 4** | 프로세스 실행 (Process Instance) |

---

#### CRISP-DM 프로세스 6단계

| 단계 | 명칭 | 주요 활동 |
|---|---|---|
| **1단계** | **업무 이해**<br>(Business Understanding) | 업무 목적 파악, 상황 파악,<br>데이터 마이닝 목표 설정, 프로젝트 계획 수립 |
| **2단계** | **데이터 이해**<br>(Data Understanding) | 초기 데이터 수집, 데이터 기술 분석,<br>데이터 탐색, 데이터 품질 확인 |
| **3단계** | **데이터 준비**<br>(Data Preparation) | 분석용 데이터셋 선택, 데이터 정제,<br>분석용 데이터셋 편성, 데이터 통합, 데이터 포매팅 |
| **4단계** | **모델링**<br>(Modeling) | 모델링 기법 선택, 모델 테스트 계획 설계,<br>모델 작성, 모델 평가 |
| **5단계** | **평가**<br>(Evaluation) | 분석 결과 평가, 모델링 과정 평가, 모델 적용성 평가 |
| **6단계** | **전개**<br>(Deployment) | 전개 계획 수립, 모니터링과 유지보수 계획 수립,<br>프로젝트 종료 보고서 작성, 프로젝트 리뷰 |

---

### KDD vs CRISP-DM 비교

| 구분 | KDD | CRISP-DM |
|---|---|---|
| **단계 수** | 5단계 | 6단계 |
| **계층 구조** | 단계 중심 | **4레벨** (단계 / 일반화 태스크 / 세분화 태스크 / 프로세스 실행) |
| **특징** | 데이터 마이닝 중심 | **업무 이해와 전개**까지 포함해 더 세부적 |

**단계 대응 관계**

| KDD | CRISP-DM |
|---|---|
| — | 업무 이해 |
| 데이터셋 선택 | 데이터 이해 |
| 데이터 전처리 | 데이터 준비 |
| 데이터 변환 | 데이터 준비 |
| 데이터 마이닝 | 모델링 |
| 해석과 평가 | 평가 / 전개 |

---

### 빅데이터 분석 방법론 계층 구조 (단계 – 태스크 – 스텝)

| 단계 (Phase) | 태스크 (Task) | 스텝 (Step) |
|---|---|---|
| **1. 분석 기획**<br>(Planning) | 비즈니스 이해 및 범위 설정 | 비즈니스 이해 / 프로젝트 범위 설정 |
| | 프로젝트 정의 및 계획 수립 | 데이터 분석 프로젝트 정의 / 프로젝트 수행 계획 수립 |
| | 프로젝트 위험 계획 수립 | 데이터 분석 위험 식별 / 위험 대응 계획 수립 |
| **2. 데이터 준비**<br>(Preparing) | 필요 데이터 정의 | 데이터 정의 / 데이터 획득 방안 수립 |
| | 데이터 스토어 설계 | 정형 데이터 스토어 설계 / 비정형 데이터 스토어 설계 |
| | 데이터 수집 및 정합성 점검 | 데이터 수집 및 저장 / 데이터 정합성 점검 |
| **3. 데이터 분석**<br>(Analyzing) | 분석용 데이터 준비 | 비즈니스 룰 확인 / 분석용 데이터셋 준비 |
| | 텍스트 분석 | 텍스트 데이터 확인 및 추출 / 텍스트 데이터 분석 |
| | 탐색적 분석 | 탐색적 데이터 분석 / 데이터 시각화 |
| | 모델링 | 데이터 분할 / 데이터 모델링 / 모델 적용 및 운영 방안 |
| | 모델 평가 및 검증 | 모델 평가 / 모델 검증 |
| **4. 시스템 구현**<br>(Developing) | 설계 및 구현 | 시스템 분석 및 설계 / 시스템 구현 |
| | 시스템 테스트 및 운영 | 시스템 테스트 / 시스템 운영 계획 |
| **5. 평가 및 전개**<br>(Deploying) | 모델 발전 계획 수립 | 모델 발전 계획 |
| | 프로젝트 평가 및 보고 | 프로젝트 성과 평가 / 프로젝트 종료 |

> **피드백 구조**: 5단계는 순차적으로 진행되지만, **데이터 준비 단계와 데이터 분석 단계**는 필요에 따라 서로 피드백을 주고받을 수 있다.
>
> 위험 대응 계획 수립단계에서는 예상되는 위험으로 부터 회피, 전이, 완화, 수용의 4가지 방법으로 대응

### 세 방법론 한눈에 비교

| 구분 | KDD | CRISP-DM | 빅데이터 분석 방법론 |
|---|---|---|---|
| **단계 수** | 5단계 | 6단계 | 5단계 |
| **계층 레벨** | — | 4레벨 | **3계층** (단계–태스크–스텝) |
| **1단계** | 데이터셋 선택 | 업무 이해 | 분석 기획 |
| **마지막 단계** | 해석과 평가 | 전개 | 평가 및 전개 |
| **특징** | 데이터 마이닝 중심 | 국제 표준, 세부적 | 시스템 구현까지 포함 |

> **핵심**: 빅데이터 분석 방법론은 **시스템 구현 단계**를 포함한다는 점에서 KDD·CRISP-DM과 구별된다.

## SEMMA 분석 방법론

SAS사가 제시한 **분석 솔루션 중심**의 5단계 방법론

| 단계 | 내용 |
|---|---|
| 추출 | 분석 데이터 생성, 표본 추출, 데이터 분할 |
| 탐색 | 통계·시각화로 데이터 탐색, 이상 현상·변화 파악 |
| 수정 | 변수 생성·선택·변환, 결측·이상값 처리 |
| 모델링 | 분석 기법 적용, 모델 구축 |
| 평가 | 모델 성능 평가·비교, 결과 보고 |

## 방법론 보충 ⭐

| 항목 | 내용 |
|---|---|
| KDD | 1996년 페이야드 등이 체계화한 데이터 마이닝 프로세스 |
| CRISP-DM | 1996년 유럽연합 ESPRIT 프로젝트에서 시작, 1999년 첫 버전 발표 |
| CRISP-DM 피드백 | 단계 간 **피드백으로 완성도를 높임** — 특히 업무 이해 ↔ 데이터 이해, 데이터 준비 ↔ 모델링 사이 반복이 잦음 |
| CRISP-DM 모델링 | 모델링 과정에서 **데이터 준비 단계로 되돌아가는 일이 빈번** |
| CRISP-DM 평가 단계 | 모델이 **프로젝트 목적에 부합**하는지 평가 (모델 자체의 성능 평가는 모델링 단계) |

### 빅데이터 분석 방법론 단계별 주요 산출물

| 단계 | 대표 산출물 |
|---|---|
| 분석 기획 | **SOW**(프로젝트 범위 정의서), 프로젝트 수행 계획서, **WBS**, 위험 관리 계획서 |
| 데이터 준비 | 데이터 정의서, 데이터 획득 계획서, 데이터 스토어 설계서, 데이터 품질 점검 보고서 |
| 데이터 분석 | 비즈니스 룰, 분석용 데이터셋, 탐색적 분석 보고서, 모델링 결과 보고서, 모델 검증 보고서 |
| 시스템 구현 | 시스템 분석·설계서, 구현 시스템, 운영 매뉴얼 |
| 평가 및 전개 | 모델 발전 계획서, 프로젝트 성과 평가서, 최종 보고서 |

> **시험 포인트**
> - 데이터 분할(훈련용·검증용)은 **데이터 분석 단계의 모델링 태스크**에 속한다
> - 데이터 시각화는 **탐색적 분석 태스크**에 속한다
> - 분석 기획의 "비즈니스 이해 및 범위 설정" 태스크 산출물이 **SOW**
> - **데이터 준비 ↔ 데이터 분석** 단계 사이에 피드백 반복
