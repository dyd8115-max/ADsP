---

## 분석 기획의 정의

| 항목 | 내용 |
|---|---|
| 정의 | 실제 분석을 수행하기에 앞서 **분석을 수행할 과제를 정의**하고, 의도한 결과를 도출할 수 있도록 **적절히 관리할 방안을 사전에 계획**하는 작업 |
| 중요성 | 어떤 목표를 위해 어떤 데이터로 어떤 방식으로 분석할지 정하는 일 — 분석 성공을 좌우하는 첫 단계 |

### 분석 기획자에게 필요한 역량 ⭐

| 역량 | 설명 |
|---|---|
| 도메인 지식 | 해당 업무·산업에 대한 이해 |
| 수학·통계학적 지식 | 분석 기법에 대한 이해 |
| 정보기술 역량 | 프로그래밍, 데이터 처리 기술 |
| 프로젝트 관리 역량, 리더십 | 위 세 가지를 조율하고 이끄는 능력 |

## 데이터 분석 기획의 이해

### 분석 기회 (Analytics Opportunity)

| 개념 | 정의 |
|---|---|
| **분석 기회** | 데이터 분석 프로젝트의 **목표, 범위, 방법, 자원을 체계적으로 계획**하는 초기 단계 |

---

## 분석 주제 (Analytics Topic)

데이터 분석 프로젝트의 성격은 **"분석 대상의 명확성"**과 **"분석 방법의 명확성"**에 따라 4가지로 분류된다.

| 분석 유형 | 분석 대상 | 분석 방법 | 설명 |
|---|---|---|---|
| **최적화** | ✅ 알고 있음 | ✅ 알고 있음 | 무엇을 분석할지, 어떻게 할지 모두 명확<br>즉시 실행 가능 |
| **솔루션** | ✅ 알고 있음 | ❌ 모름 | 문제는 알지만 해결 방법을 찾아야 함<br>신기술이나 새로운 기법 도입 필요 |
| **발견** | ❌ 모름 | ❌ 모름 | 문제와 해결책 모두 불명확<br>탐색적 분석 필요 |
| **통찰** | ❌ 모름 | ✅ 알고 있음 | 분석 기법은 알지만 어디에 적용할지 모름<br>새로운 기회 탐색 |

> **선택 기준**: 조직의 성숙도와 문제 상황에 따라 적절한 분석 유형을 선택해야 한다.

## 목표 시점별 분석 기획

분석 프로젝트의 추진 방식은 조직의 목표 시점에 따라 크게 두 가지로 나뉜다.

| 접근 방식 | 목표 시점 | 핵심 지향점 |
|---|---|---|
| **과제 중심적 접근 방식** | 단기 | 당면한 과제를 빠르게 해결 |
| **장기적 마스터 플랜 방식** | 중장기 | 지속적인 분석 문화의 내재화 |

---

### 두 방식의 비교

| 구분 | 과제 중심적 접근 방식 | 장기적 마스터 플랜 방식 |
|---|---|---|
| **1차적 목표** | **Speed & Test**<br>(속도와 시험) | **Accuracy & Deploy**<br>(정확도와 적용) |
| **과제의 유형** | **Quick & Win**<br>(빠른 성과 확보) | **Long Term View**<br>(장기적 관점) |
| **접근 방식** | **Problem Solving**<br>(문제 해결) | **Problem Definition**<br>(문제 정의) |

> **핵심 차이**: 과제 중심은 "**주어진 문제를 빨리 푸는 것**"에, 마스터 플랜은 "**무엇이 문제인지 정확히 정의하는 것**"에 초점을 둔다.

---

### 각 방식의 상세

#### 1️⃣ 과제 중심적 접근 방식

| 항목 | 내용 |
|---|---|
| **적용 상황** | 빠르게 해결해야 하는 당면 과제가 있을 때 |
| **1차적 목표 (Speed & Test)** | 일단 빠르게 분석해보고 결과를 검증<br>완벽함보다 속도가 우선 |
| **과제 유형 (Quick & Win)** | 단기간에 눈에 보이는 성과를 낼 수 있는 과제 선정<br>작은 성공으로 조직의 신뢰 확보 |
| **접근 방식 (Problem Solving)** | 문제가 이미 정의되어 있다는 전제로 **해결에 집중** |

---

#### 2️⃣ 장기적 마스터 플랜 방식

| 항목 | 내용 |
|---|---|
| **적용 상황** | 지속적인 분석 내재화를 목표로 할 때 |
| **1차적 목표 (Accuracy & Deploy)** | 정확도를 확보하고 실제 업무에 안정적으로 적용<br>속도보다 신뢰성이 우선 |
| **과제 유형 (Long Term View)** | 전사적 관점에서 우선순위를 정하고 단계적으로 추진 |
| **접근 방식 (Problem Definition)** | "무엇이 진짜 문제인가"를 정의하는 것부터 시작 |

---

> **선택 기준**: 조직의 분석 성숙도가 낮다면 Quick & Win 과제로 시작해 신뢰를 얻고, 이후 마스터 플랜으로 확장하는 것이 일반적이다.

## 분석 기획 시 고려사항

### 1️⃣ 가용 데이터 고려

| 내용 | 설명 |
|---|---|
| **데이터 확보 가능성** | 분석에 필요한 데이터가 **실제로 존재하고 확보 가능한지** 확인 |
| **데이터 유형 분석** | 확보 가능한 데이터의 **유형에 따라 분석 방법이 달라짐**<br>정형/비정형, 정량/정성 데이터에 따라 기법 선택 |
| **선행 분석** | 데이터 유형에 대한 분석이 **기획 단계에서 선행되어야 함** |

> **중요**: "데이터가 있으니 분석하자"가 아니라, "분석 목표를 위해 필요한 데이터가 있는지 확인"하고 기획해야 한다.

---

### 2️⃣ 적절한 활용방안과 유스케이스 탐색

| 내용 | 설명 |
|---|---|
| **기존 사례 활용** | 이미 **구현되어 성공하고 있는 유사한 분석 사례를 최대한 활용** |
| **과거 교훈 반영** | 과거의 **유사 분석 사례가 있다면 그 시나리오를 참조**<br>실패 사례로부터 실수 회피, 성공 사례로부터 가이드 확보 |
| **재사용성** | 이미 검증된 솔루션을 재활용해 **개발 시간과 비용 절감** |

> **핵심**: 바퀴를 다시 발명하지 말고, 기존의 검증된 방식을 활용한다.

---

### 3️⃣ 장애요소에 대한 사전 계획 수립

| 내용 | 설명 |
|---|---|
| **위험 요소 식별** | 분석 수행 중 발생 가능한 **장애요소를 미리 파악** |
| **대응 계획 수립** | 각 위험 요소별 **사전 대응 방안을 구체적으로 계획** |
| **완화 전략** | 위험을 완전히 제거할 수는 없지만, **그 영향을 최소화**하는 전략 |

**예상 장애요소**
- 데이터 품질 문제
- 데이터 접근 권한 제한
- 인력/자원 부족
- 기술적 난제
- 조직 내 저항

> **사전 예방이 사후 대응보다 낫다**: 기획 단계에서 충분히 검토해야 프로젝트 성공률이 높아진다.

## 분석 기획의 체크리스트

분석 기획 수립 시 다음을 확인하자.

| 항목 | 확인 사항 |
|---|---|
| **분석 대상** | 분석해야 할 주제가 명확하게 정의되었는가? |
| **분석 방법** | 해당 분석을 위한 기법이 정해졌는가? |
| **가용 데이터** | 필요한 데이터가 실제로 확보 가능한가? |
| **유사 사례** | 참고할 수 있는 기존 사례나 시나리오가 있는가? |
| **장애 요소** | 예상되는 위험 요소와 대응책이 준비되었는가? |
| **자원 계획** | 필요한 인력, 도구, 시간이 할당되었는가? |

> **결론**: 철저한 기획이 성공적인 분석의 출발점

## 분석 기획 시 고려사항 — 교재 표현 ⭐

| 고려사항 | 핵심 |
|---|---|
| 가용 데이터 | 데이터 유형에 따라 **적용 가능한 솔루션과 분석 방법이 달라짐** — 정형: ERP·CRM 등의 DB / 반정형: 센서·로그·XML / 비정형: 텍스트·영상·음성 |
| 활용 방안과 유스케이스 | 유사 분석 시나리오와 **이미 검증된 솔루션을 최대한 활용** |
| 장애요소 사전 계획 | 일회성 분석이 아닌 **조직 역량 내재화**가 목적 — 충분하고 계속적인 교육과 **변화관리** 고려 |

**분석 수행 시 고려할 장애요소 예**

- 정확도를 높이려면 기간·투입 자원이 늘어 **비용이 상승**
- 분석 결과를 사용자가 이해하기 어려우면 활용되지 않음 → **사용자 이해도**를 높이는 시각화·교육 필요
- 실제 환경에서 **분석 모형의 안정적 성능** 확보
