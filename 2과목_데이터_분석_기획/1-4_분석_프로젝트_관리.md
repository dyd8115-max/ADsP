# 분석 프로젝트 관리 방안

> 2과목 데이터 분석 기획 › 1장 데이터 분석 기획의 이해

---

## 분석 프로젝트의 특징

| 특징 | 내용 |
|---|---|
| 두 영역의 이해 | 분석가는 **데이터 영역과 비즈니스 영역**을 모두 이해해야 함 |
| 조율자 역할 | 분석가는 프로젝트 관리자로서 데이터·현업·IT 전문가 사이를 **조율** |
| 반복과 정교화 | 도출된 결과를 재해석하며 **지속적으로 반복·정교화**하는 경우가 대부분 |
| 관리 방식 | 그래서 **프로토타이핑 방식의 애자일 프로젝트 관리**를 고려 |

---

## 분석 과제의 5가지 주요 특성 ⭐

분석 과제를 관리할 때 고려해야 할 특성 (시험에 영문 표기로도 나옴)

| 특성 | 관리 포인트 |
|---|---|
| **데이터 크기** (Data Size) | 분석할 데이터 양 — 하둡 같은 대용량 처리 환경과 기존 정형 DB 환경은 관리 방식이 다름 |
| **데이터 복잡도** (Data Complexity) | 정형·비정형, 여러 시스템에 흩어진 원천 데이터를 통합할 때 **적합한 플랫폼과 모델** 선택 |
| **속도** (Speed) | 분석 결과가 **활용되는 시나리오 측면의 속도** — 배치 처리인지 실시간인지 |
| **분석 복잡도** (Analytic Complexity) | 정확도와 복잡도는 **트레이드오프** — 해석이 가능하면서도 정확도를 확보할 최적 모델 |
| **정확도와 정밀도** (Accuracy & Precision) | 정확도: 모델과 실제 값의 차이가 적은 정도 — **활용 측면** / 정밀도: 반복했을 때 결과 편차가 적은 정도 — **안정성 측면** |

> 정확도와 정밀도는 **트레이드오프가 되는 경우가 많다**. 모델 활용 목적에 따라 우선순위를 정해야 한다.

## 10가지 관리 영역 ⭐

국제 표준 ISO 21500(국내 KS A ISO 21500) 기반의 프로젝트 관리 영역

| 영역 | 분석 프로젝트에서의 특징 |
|---|---|
| **통합** | 프로젝트의 여러 프로세스가 통합적으로 운영되도록 관리 |
| **이해관계자** | 데이터·분석·비즈니스 전문가 등 다양한 이해관계자 식별·관리 |
| **범위** | 데이터 형태·양, 적용 모델에 따라 **범위가 빈번히 변경** — 최종 결과물이 보고서인지 시스템인지에 따라 범위가 크게 달라짐 |
| **자원** | 고급 분석·빅데이터 아키텍처 등 **전문 인력 확보** |
| **시간** | 초기 의도한 모델이 쉽게 나오지 않아 지연 가능 → 품질을 보장하는 전제로 **타임 박싱**으로 일정 관리 |
| **원가** | 외부 데이터 구입, 상용 도구·인프라 비용 등 사전 검토 |
| **리스크** | 데이터 미확보, 품질·보안 문제 등을 식별하고 **회피·전이·완화·수용**으로 대응 |
| **품질** | 품질 통제와 품질 보증으로 나누어 수행 |
| **조달** | 외부 소싱 적절히 활용 — 개념 검증(PoC) 단계에선 인프라 구매보다 클라우드 등 고려 |
| **의사소통** | 전문성이 요구되므로 이해관계자 모두가 **결과를 공유**할 수 있는 소통 체계 |
